从 Java OOM 到稳定跑完 320 万数据：一次 PostgreSQL + Java 批处理内存问题的完整排查与优化

本文记录一次真实的 Java + PostgreSQL 大数据量处理场景中的 OOM 排查过程。
核心问题是：一次性查询约 320 万条用户数据，并在 Java 内存中进行多阶段关联、补充指标和组装实体，最终导致 JVM 堆内存逼近上限甚至 OOM。

最终通过滑动窗口 + 单 Map 分批处理 + 及时解除原始 List 引用 + 小批量落库的方式，将原本存在 OOM 风险的处理流程改造成可以稳定完成 320 万数据处理的方案。

同时也总结了为什么一些看似合理的优化方式实际上没有降低内存，以及如何通过日志快速判断到底是“内存泄漏”还是“GC 尚未及时回收”。
